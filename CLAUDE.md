## ⭐ ТЕКУЩЕЕ СОСТОЯНИЕ ДЛЯ ПРОДОЛЖЕНИЯ (читать первым)

### Как работать (важно, Windows)
- Запуск: `npm run dev` (поднимается на **http://localhost:3001**, порт 3000 занят).
- **НЕ запускать `npm run build` поверх работающего `next dev`** — бьёт `.next` и
  ломает все вкладки. Перед сборкой остановить dev (освободить порт 3001), затем
  `rm -rf .next && npm run build`, потом снова `npm run dev`.
- Проверка на каждом шаге: `npx tsc --noEmit` (быстро, без конфликта с dev).
- Логин: `Ggmlynarchik21@gmail.com` (роль admin).

### ⚠️ Миграции Supabase — применить в SQL Editor по порядку
Лежат в `supabase/migrations/`. Без них модули работают с фолбэками, но не полноценно:
- `002_lead_dedup_and_history.sql` — дедуп лидов + история (activity_logs).
- `003_project_stages.sql` — `projects.stages` (JSONB) — этапы проекта.

- `005_expenses.sql` — таблица `expenses` (расходы/прибыль/ROI).

## Дедупликация лидов и история (новое)
- **Дедуп лидов** (`lib/lead-dedup.ts`): при создании лида считается сходство
  с существующими по контактам (телефон/email/telegram) и имени:
  - `≥50%` → слияние в существующего лида, заполняются только пустые поля
    (старое не теряется, заметки дописываются), новый лид не создаётся
  - `0 < сходство < 50%` → новый лид создаётся отдельно с пометкой `is_duplicate`
    и ссылкой `duplicate_of` + `similarity_score`
  - совпадений нет → обычное создание
  - подключено в `leads/actions.ts` (createLead) и в Telegram lead-bot вебхуке
  - **fallback**: если миграция 002 не применена — лид создаётся как обычно, дедуп
    включится автоматически после применения миграции
- **История** (`lib/history.ts`, таблица `activity_logs`): фиксируются события —
  регистрация лида, слияние, пометка дубля, смена статуса, редактирование,
  конвертация в клиента, обращение в поддержку.
  - таймлайн `components/shared/HistoryTimeline.tsx`
  - показывается в карточке лида (блок «История») и в карточке клиента
    (вкладка «История», включает события клиента + исходного лида)
- **Бейдж «Дубль»**: в карточке лида (со ссылкой на оригинал и % сходства)
  и в списке лидов.
- **Миграция**: `supabase/migrations/002_lead_dedup_and_history.sql` — применить
  в Supabase SQL Editor (добавляет колонки в `leads` и индексы).
