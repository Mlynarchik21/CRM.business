# ТЗ на доработку Studio CRM (v3)

> Составлено в роли «живого пользователя» — владельца digital-студии,
> который ежедневно ведёт лиды → клиентов → проекты → оплаты и хочет
> подключать трафик и ИИ-агентов. Включает правки заказчика + найденные
> в ходе «прогона» пробелы. Дата: 2026-05-22.

---

## 0. Персона и сценарий прогона

**Алекс**, владелец студии. Утро: смотрит дашборд → новые лиды → отвечает →
переводит в клиента → заводит проект и этапы → выставляет оплату → вечером
смотрит деньги и откуда пришёл трафик. Параллельно хочет «нанять» ИИ-агентов
(холодный поиск, авто-ответы) и следить за ними.

Где сейчас спотыкается (выводы прогона) — ниже по разделам.

## A. Правки заказчика (обязательно)

### A1. Маркетинг — переделать
- Главный экран раздела = **статистика трафика** (а не плейбук-карточки):
  - источников всего / активных,
  - лидов по источникам за период,
  - конверсия источника в клиента, стоимость лида (если задан бюджет).
- Вместо кнопки **«Сохранить»** — кнопка **«Добавить»**: по клику открывается
  **форма добавления источника трафика** (модалка), а не правка всего списка разом.
- Плейбук-подсказки (где взять API, куда вставить) оставить, но убрать в
  «справку»/при добавлении источника, не на главный экран.

### A2. Агенты — переделать
- Сверху — **статистика**: сколько агентов работает, на паузе, с ошибкой.
- Ниже — **список агентов**: что за агент, **как давно работает**, **статус**
  (работает / на паузе / ошибка).
- **Клик по агенту → раскрытие полного описания.** Если ошибка — показать
  **текст ошибки**, всё **копируемое** (кнопка «Скопировать»).
- Кнопки **«Настройки» / «Редактировать бота»** прямо в карточке.
- Внутри настроек агента: менять **промпт**, подгружать **скилы**, смотреть
  **аналитику** агента, менять **API-ключ** — всё внутри CRM.
- Вместо **«Сохранить»** на главном — кнопка **«Добавить»** (форма нового агента).
- Цель: качественно следить за каждым агентом, понимать метрики, настраивать.

### A3. Оплаты — кнопка «Расходы»
- На странице оплат добавить кнопку **«Расходы»** → переключение в раздел
  расходов, где вносим расходные показатели (статья, сумма, дата, проект/категория).
- Это даёт расчёт **прибыли = доход − расход** (см. B2, B4).

### A4. Задачи — переделать в стиль «Этапы проекта»
- Блок «Задачи» — внутренний трекер «для нас» (см. скрин).
- **Компактный список с раскрытием деталей по клику** (как этапы):
  - `#N  Название`, краткое описание-превью;
  - чек-выполнения слева;
  - **карандаш-редактирование** в каждом блоке;
  - меню «...» (доп. действия), drag для порядка;
  - кнопки **«Шаблоны»** и **«Добавить»** сверху.
- **Добавление через кнопку** «Добавить» → открывается **окно** (модалка), а не
  инлайн-поле.
- Прогресс/счётчик выполненных, как в этапах.

### A5. Этапы проекта — правки (из заметки на скрине)
- В **каждом блоке — кнопки редактирования** (карандаш), быстро и заметно.
- Вкладку «Этапы» сделать **компактнее**.
- **Добавление этапа — по кнопке** «Добавить» → всплывает окно (а не инлайн).
- Почистить демо-данные: в текущем проекте в описание этапа #1 случайно
  записан текст-заметка — убрать.

## B. Найденные пробелы (предлагаю, «новые функции приветствуются»)

### B1. Лиды под холодный поиск (нужно для агента холодного поиска)
Отдельные поля БД вместо «всё в заметках»:
- где найден (площадка/ссылка), тип бизнеса, сайт/соцсети/карты,
- срок работы бизнеса, что уже есть, **что можем предложить**, ориентир бюджета.
Это же — формат, который заполняет агент холодного поиска.

### B2. Расходы и P&L
- Таблица `expenses` (категория, сумма, валюта, дата, проект?, источник трафика?).
- Дашборд и аналитика: **доход / расход / прибыль / маржа**.
- Связь с маркетингом: расход на источник → стоимость лида и ROI источника.

### B3. Аналитика — переключатель и метрики
- Тумблер **«Финансы / сделки» ↔ «Трафик»**.
- Финансы: выручка по месяцам, прибыль, средний чек, LTV клиента, won-rate.
- Трафик: лиды по источникам, **конверсия источника**, выручка с источника, ROI.
- Воронка: лид → клиент → проект → оплата (с процентами перехода).

### B4. Дашборд
- Карточка **Прибыль** (после ввода расходов).
- Виджет «Агенты»: сколько работает / ошибки (ссылка в раздел).
- Уже добавлены: задачи/оплаты/поддержка — оставить.

### B5. Единый паттерн карточек
- Везде «строка → окно деталей → Изменить» (как теперь в оплатах): применить
  к клиентам/проектам/лидам для единообразия (опционально, по желанию).

### B6. Пагинация 25/50
- Добавить в **Клиенты, Проекты, Поддержка** (в Лидах и Оплатах уже есть).

### B7. Настройки → Подключения
- Возможность добавлять **сторонние API** (название, ключ, endpoint, статус),
  не только наши. Используется агентами/маркетингом.

## C. Технические риски и важное

- **API-ключи агентов сейчас хранятся в таблице `settings` (БД) открытым текстом** —
  это MVP-решение. Для продакшна: шифрование/Supabase Vault или хранение в `.env`
  со ссылкой из CRM. Заложить в дизайн агента.
- **Файлы (чеки, файлы этапов) грузятся в локальные `/api/*`** — на Vercel
  файловая система эфемерна, файлы пропадут. Нужен **Supabase Storage**.
- **Миграции 002/003/004 должны быть применены** в Supabase (дедуп лидов,
  этапы проекта, 4 статуса оплат). Без них часть функций деградирует (есть
  безопасные фолбэки, но фичи не работают полноценно).
- **Telegram-боты** требуют реальных токенов + `setWebhook` после деплоя.
- **Windows dev**: не запускать `next build` поверх `next dev` (бьёт `.next`,
  ломает все вкладки). Сборку делать с остановленным dev.
- **Роли/RLS**: сейчас MVP-политики (любой authenticated видит всё). V2 — по ролям.

## D. «Агент-ревьюер» (как просил — симулятор живого пользователя)

Предлагаю как отдельную фичу: встроенный агент-ревьюер, который периодически
«проходит» по данным CRM (пустые поля, зависшие лиды без действий, просроченные
задачи/оплаты, проекты без этапов) и выдаёт **список улучшений и подсказок**.
Это и есть «живой пользователь», встроенный в систему. (Реализуем после базы.)

## E. Предлагаемый порядок работ

1. **Задачи → стиль этапов** + правки самих этапов (A4, A5) — быстро, по образцу.
2. **Агенты — редизайн** (A2): статистика, список, статусы, раскрытие, ошибки,
   копирование, «Добавить» через форму, настройки агента (промпт/скилы/API).
3. **Маркетинг — редизайн** (A1): статистика + «Добавить» формой.
4. **Расходы + кнопка «Расходы» в оплатах** (A3, B2) + миграция `expenses`.
5. **Пагинация** в клиентах/проектах/поддержке (B6).
6. **Аналитика**: переключатель + метрики + трафик/ROI (B3).
7. **Лиды под холодный поиск** (B1) + поля БД.
8. **Подключения: сторонние API** (B7).
9. Тех-долг: Supabase Storage для файлов, шифрование ключей (C).
